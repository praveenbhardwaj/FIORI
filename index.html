Web FundamentalsStart here

The Path into SAPUI5

SAPUI5 is still HTML, CSS, and JavaScript — wrapped in XML views, a control tree, and MVC. These lessons teach only the web pieces you need to read a controller, not a full frontend-engineering course.

After this section the existing path continues: MVC → data binding → OData → routing → a full Fiori application.

LayerWhat it definesUI5 equivalent
HTMLWhat exists on the pageXML View — what controls exist
CSSHow it looks and is laid outFiori theme + class / sapUi* spacing
JavaScriptWhat happens when the user actsController event handlers
⚠️
Do not try to learn “all of JavaScript.” The goal is to look at onSave: function (oEvent) and immediately see a function, an event, this, a method call, a string, and an if.
HTMLMental model

What is HTML?

HTML defines what exists on the page — headings, buttons, inputs, lists. It is not a programming language. It is a structure language, the same job an XML View does in SAPUI5.

html
<!DOCTYPE html>
<html>
<head>
    <title>My Page</title>
</head>
<body>
    <h1>Hello Fiori</h1>
</body>
</html>
HTML
html
<button>Save</button>
UI5 XML View
xml
<Button text="Save" />
💡
HTML → page structure. XML View → UI structure. Once that mapping clicks, XML Views stop looking foreign.
Exercise: Write a page with a title “Employee App” and a heading “Employee List”. Do not add CSS yet.

HTMLBuilding blocks

Elements & Attributes

An element is a tag plus its content. An attribute is extra information on the opening tag — id, src, type, href. UI5 XML uses the same idea: a control name plus properties.

html
<input id="nameInput" type="text" placeholder="Name">

Self-closing tags (<img>, <input>, <Button />) have no inner text. Most UI5 controls are written this way when they have no children.

CSSMental model

What is CSS?

CSS defines how it looks. HTML says “there is a button.” CSS says how large, how spaced, what colour. In Fiori, SAP’s theme does most of this. You still need CSS literacy to debug layout and to apply the official spacing classes.

css
.card {
    background-color: lightgray;
    color: black;
    font-size: 20px;
    text-align: center;
}
⚠️
Do not restyle Fiori controls to look like a custom website. Follow the theme. Custom CSS is for spacing, rare layout fixes, and your own non-control wrappers — not for reinventing sap.m.Button.

Colour, type, and size are the first properties people reach for. In UI5, theme parameters already define brand colours and typography — override them only when you have a reason.

The Box Model

Every element is a rectangle made of content, padding, border, and margin. Layout bugs in Fiori custom CSS are almost always a box-model misunderstanding.

margin · 30px
border · 1px
padding · 20px
content · width 300px
css
.card {
    width: 300px;
    padding: 20px;
    border: 1px solid black;
    margin: 30px;
}

ℹ️
Fiori spacing classes such as sapUiSmallMargin and sapUiTinyMarginBegin are just pre-defined margins. They exist so you do not invent your own 13px gaps.

CSS Grid & Responsive Design

Grid places items on rows and columns. Media queries change rules at a breakpoint. Fiori already ships responsive tables and a form grid — learn the idea so those controls feel less like magic.

css
.layout {
    display: grid;
    grid-template-columns: 1fr 1fr;
    gap: 16px;
}

@media (max-width: 600px) {
    .layout { grid-template-columns: 1fr; }
}

On a phone, two columns become one. That is the same instinct as sap.ui.layout.form.SimpleForm switching from two columns to one, or a ResponsiveTable collapsing columns.

JavaScriptLevel 1

JavaScript Fundamentals

JavaScript is the language of every SAPUI5 controller. You do not need a frontend-engineering course. You need to recognise functions, objects, methods, events, and this when you read code like this:

javascript — the target
onSave: function (oEvent) {
    var oInput = this.byId("nameInput");
    var sName = oInput.getValue();

    if (sName) {
        MessageToast.show("Hello " + sName);
    }
}

By the last lesson you should be able to name every piece of that snippet. Open the browser console (F12 → Console) and run console.log("Hello") — that is your scratchpad for the next lessons.

JavaScriptSyntax

Variables

A variable is a named box. SAPUI5 controllers still contain a lot of var. New code should prefer const and let.

javascript
var name = "Praveen";
var age = 30;
console.log(name);

let city = "Delhi";       // can be reassigned
const company = "SAP";    // cannot be reassigned
KeywordReassign?When to use
varYes (function scoped)Reading older UI5 samples
letYesValues that change
constNoDefault for new code
ℹ️
Hungarian notation in UI5: sName string, oInput object, aItems array, bValid boolean, iCount integer, fnCallback function. You will see it everywhere.
JavaScriptData

Data Types & Operators

Controllers pass strings, numbers, booleans, objects, and arrays. typeof and a few operators cover most conditions you will write.

javascript
var name = "John";      // String
var age = 25;            // Number
var active = true;       // Boolean
var value = null;        // Null — intentionally empty
var x;                   // Undefined — not set yet

typeof name;             // "string"
10 + 20;                 // 30
"Hello " + name;         // "Hello John"
age >= 18;               // true
"5" === 5;               // false — always prefer ===
⚠️
Use === not ==. UI5 code reviews will flag loose equality. == coerces types and hides bugs.
JavaScriptDecisions

Conditions

An if runs code only when a test is true. Empty strings, 0, null, and undefined are all falsy — which is why if (sName) is a common “did the user type something?” check.

Plain JavaScript
javascript
var age = 25;
if (age >= 18) {
    console.log("Adult");
} else {
    console.log("Minor");
}
UI5 controller
javascript
if (sName) {
    MessageToast.show("Name entered");
} else {
    MessageToast.show("Please enter a name");
}
JavaScriptRepetition

Loops

Loops walk lists. In UI5 you more often use forEach / map / filter on JSON model data than a raw for — but you must still be able to read both.

javascript
var cities = ["Delhi", "London", "Berlin"];

for (var i = 0; i < cities.length; i++) {
    console.log(cities[i]);
}

for (var sCity of cities) {
    console.log(sCity);
}
JavaScriptCritical

Functions

A function is a named (or anonymous) block you can call. Every onInit, onSave, and onNavBack is a function stored as a property on the controller object. Learn function first. Arrow functions come later.

javascript
function add(a, b) {
    return a + b;
}
var result = add(10, 20);   // 30

function sayHello(name) {
    console.log("Hello " + name);
}
sayHello("Praveen");

Parameters receive values. return sends a value back. If there is no return, the function returns undefined.

Then modern syntax

javascript
const add = (a, b) => {
    return a + b;
};
const addShort = (a, b) => a + b;
⚠️
Arrow functions do not bind their own this. That is why UI5 controller methods are still usually written as onSave: function () { this.byId(...) }, not as arrows, unless you already understand this.
JavaScriptCritical for UI5

Objects

An object is a bag of named properties. A method is a function stored as a property. this.byId() only makes sense once you see that this is an object and byId is a method on it.

javascript
var employee = {
    name: "John",
    age: 30,
    department: "IT"
};

console.log(employee.name);
employee.age = 31;
employee.city = "Delhi";

employee.getDetails = function () {
    return this.name + " - " + this.department;
};
employee.getDetails();
💡
this.getView() is the same pattern: call the getView method on the current controller object. That is one of the biggest conceptual hurdles for junior UI5 developers.
Exercise: Create an object product with name and price. Add a method describe that returns both. Call it.
JavaScriptLists

Arrays

An array is an ordered list. JSON models in UI5 are usually arrays of objects — exactly the shape of an OData entity set in memory.

javascript
var employees = ["John", "Smith", "David"];
employees[0];   // "John"

var rows = [
    { name: "John",  age: 30 },
    { name: "Smith", age: 25 }
];
rows[0].name;   // "John"
JavaScriptJSON model data

Array Methods

forEach, map, filter, and find are how you reshape model data before putting it back on a JSONModel — search boxes, status chips, “active employees only.”

javascript
var employees = [
    { name: "John",  active: true },
    { name: "Smith", active: false }
];

var active = employees.filter(function (employee) {
    return employee.active === true;
});

var names = employees.map(function (e) { return e.name; });
var john = employees.find(function (e) { return e.name === "John"; });

JavaScriptWhy controllers look like this

Events

An event is “something happened.” Vanilla JS listens with addEventListener. UI5 wires the XML press property to a controller function. That is why controllers are full of on* methods.

Vanilla JS
javascript
button.addEventListener("click", function () {
    console.log("Button clicked");
});
SAPUI5
xml + js
<Button
    text="Save"
    press=".onSave" />

onSave: function (oEvent) {
    console.log("Button clicked");
}

oEvent is a parameter — an object describing the event. oEvent.getSource() is the control that fired it. oEvent.getParameter("listItem") is how list item presses pass extra data.

JavaScriptMust-have

JSON

JSON is a text format for objects and arrays. A JSONModel is a browser-side store of that shape. If you can read JSON, the existing JSON Model article on this site becomes obvious.

javascript
var employee = {
    name: "John",
    age: 30,
    skills: ["JavaScript", "SAPUI5"]
};

var jsonString = JSON.stringify(employee);
var back = JSON.parse(jsonString);
javascript — JSONModel
var oModel = new sap.ui.model.json.JSONModel({
    employee: { name: "John", age: 30 }

JavaScriptReal Fiori work

Promises & async / await

OData calls are asynchronous — the answer arrives later. A Promise represents that later value. UI5 v2 OData still uses success/error callbacks; newer APIs and fetch use Promises. You need both.

javascript
fetch("/employees")
    .then(function (response) {
        return response.json();
    })
    .then(function (data) {
        console.log(data);
    });

async function loadEmployees() {
    const response = await fetch("/employees");
    const data = await response.json();
    console.log(data);
}

Compare with classic ODataModel:

javascript
oModel.read("/Employees", {
    success: function (oData) { console.log(oData.results); },
    error:   function ()      { MessageToast.show("Read failed"); }
});
JavaScriptHow UI5 loads files

Modules & Error Handling

sap.ui.define is UI5’s module system — AMD. Each controller file declares dependencies, receives them as function parameters, and returns a class. try / catch stops a thrown error from killing the whole app.

javascript
sap.ui.define([
    "sap/ui/core/mvc/Controller",
    "sap/m/MessageToast"
], function (Controller, MessageToast) {
    "use strict";
    return Controller.extend("demo.controller.Main", {
        onSave: function () {
            try {
                MessageToast.show("Saved");
            } catch (err) {
                console.error(err);
            }
        }
    });
});
PieceMeaning
Dependency arrayModules to load (paths, not variables)
Factory function paramsThe loaded modules, in the same order
"use strict"Catches sloppy JS (undeclared vars)
Controller.extendCreate a subclass — your controller

SAP Business Technology Platform

SAP BTP is SAP's cloud platform for building, extending, and integrating enterprise applications. It unifies database, analytics, application development, AI, and integration capabilities under a single managed environment.

Core Services Used in Fiori Development

PaaS environment where apps are deployed. Handles servers, scaling, and execution automatically.

Managed BTP service that hosts and serves SAPUI5 static files. All deployed Fiori apps live here.

Named HTTP connection registry. Stores backend URLs and authentication config — referenced by name from apps.

Handles OAuth2-based user authentication and role-based access control for BTP apps.

PlatformBTP Connectivity

BTP Destination Service

A Destination is a named, reusable connection configuration stored in BTP. Instead of hardcoding backend URLs in application code, you reference a destination name — BTP resolves the actual URL, auth method, and proxy settings at runtime.

Northwind OData Destination Setup

FieldValue
NameNorthwind (case-sensitive)
TypeHTTP
URLhttps://services.odata.org
Proxy TypeInternet
AuthenticationNoAuthentication
Additional PropertyWebIDEUsage = odata_gen
⚠️
Case sensitivity: The destination name Northwind must match exactly what is declared in manifest.json under sap.app.dataSources. A mismatch causes a 404 at runtime with no obvious error message.

Referencing a Destination in manifest.json

json — manifest.json
"sap.app": {
  "dataSources": {
    "northwindService": {
      "uri": "/V2/Northwind/Northwind.svc/",
      "type": "OData",
      "settings": { "odataVersion": "2.0" }
    }
  }
}

The URI /V2/Northwind/Northwind.svc/ is appended to the destination's base URL automatically. The full resolved URL becomes https://services.odata.org/V2/Northwind/Northwind.svc/.

PlatformCloud Foundry

Deploying to BTP Cloud Foundry

SAPUI5 apps are packaged as Multi-Target Application (MTA) archives and deployed to BTP's Cloud Foundry runtime. BAS provides both a UI-based and CLI-based deployment path.

Deployment Prerequisites

  • mta.yaml — deployment descriptor present in the project root
  • CF environment activated in your BTP subaccount
  • HTML5 Application Repository service entitlement enabled
  • CF API endpoint URL (find in BTP Cockpit → Subaccount → Cloud Foundry)

Method 1 — BAS UI Deploy

  1. Right-click mta.yaml → Build MTA Project
  2. Press F1 → type CF: Login to Cloud Foundry → enter API endpoint + credentials → select org and space
  3. Expand mta_archives/ → right-click the .mtar file → Deploy MTA Archive
  4. Monitor progress in the terminal panel. On success: "Process finished. (state: DONE)"
  5. BTP Cockpit → Subaccount → HTML5 Applications → click app name to get the live URL

Method 2 — CF CLI

bash
# Authenticate
cf login -a https://api.cf.us10-001.hana.ondemand.com

# Verify target
cf target

# Build the MTA archive
mbt build
# Produces: mta_archives/northwind_0.0.1.mtar

# Deploy
cf deploy mta_archives/northwind_0.0.1.mtar

# Verify apps are running
cf apps

# View logs if something fails
cf logs northwind-app-deployer --recent

XML View Anatomy

In SAPUI5, the preferred view format is XML. XML Views declare the UI control tree declaratively — each XML element maps to a UI5 control class, and attributes map to control properties.

xml
<mvc:View
  controllerName="northwind.controller.Home"
  xmlns:mvc="sap.ui.core.mvc"
  xmlns="sap.m"
  xmlns:l="sap.ui.layout">

  <Page title="{i18n>homeTitle}">
    <headerContent>
      <Button icon="sap-icon://add" press=".onAdd"/>
    </headerContent>
    <content>

    </content>

XML Namespace Declarations

DeclarationEffect
xmlns="sap.m"Default namespace — controls like <Button> resolve to sap.m.Button
xmlns:mvc="sap.ui.core.mvc"Required for the root <mvc:View> element

Views & ControllersController

Controller Structure & Lifecycle

A controller is a JavaScript module that handles the event-driven logic for a single view. It follows the AMD module pattern via sap.ui.define.

javascript
sap.ui.define([
  "sap/ui/core/mvc/Controller"
], function(Controller) {
  "use strict";

  return Controller.extend("northwind.controller.Home", {

    onInit: function() {
      // Runs once when view is created
      // Use for: model setup, router listeners, initial data fetch
    },

    onBeforeRendering: function() {
      // Runs before each render cycle — rarely needed
    },

    onAfterRendering: function() {
      // Runs after view is in the DOM — use sparingly
    },

    onExit: function() {
      // Runs on view destruction — clean up timers, listeners
    },

    onButtonPress: function() {
      // Custom handler — referenced in View via press=".onButtonPress"
      sap.m.MessageToast.show("Pressed!");
    }

  });
});

Lifecycle Hook Reference

HookWhen it firesTypical use
onInitOnce, when the view is instantiatedSet models, attach route listeners, load initial data
onBeforeRenderingBefore each renderRarely used; avoid heavy operations
onAfterRenderingAfter view is in the DOMDOM access (avoid if possible — let binding handle updates)
onExitWhen view is destroyedDestroy fragments, clear timers, unsubscribe events

Fragments & Dialogs

A Fragment is a reusable XML UI snippet without its own controller. The most common use case is Dialogs — keeping them in separate fragment files keeps views clean and enables reuse.

Fragment File — CreateEmployee.fragment.xml

xml
<core:FragmentDefinition
  xmlns="sap.m"
  xmlns:core="sap.ui.core">

  <Dialog title="Create Employee">
    <content>
      <SimpleForm>
        <Label text="First Name"/>
        <Input value="{newEmp>/firstName}"/>
      </SimpleForm>
    </content>

      <Button text="Save" type="Emphasized" press=".onSave"/>
      <Button text="Cancel" press=".onClose"/>
    </buttons>

Controller — Load and Manage Dialog

javascript
onOpenDialog: function() {
  if (!this._oDialog) {
    // Load once, cache reference — avoid re-loading on every open
    this._oDialog = sap.ui.xmlfragment(
      "northwind.view.CreateEmployee",
      this   // passes controller as event handler scope
    );
    this.getView().addDependent(this._oDialog);
  }
  this._oDialog.open();
},
onClose: function() { this._oDialog.close(); }
⚠️
Always call addDependent() — this attaches the dialog to the view's lifecycle so it is properly destroyed when the view is destroyed, preventing memory leaks.

RoutingConfiguration

Router Configuration

The SAPUI5 Router manages Single Page Application navigation by watching URL hash changes. All routing configuration lives in manifest.json and the Router is initialised in Component.js.

Core Concepts

Router

Watches hash changes, activates the matching route, and loads the target view.

Route

Maps a URL pattern to a target. Name is used in code; pattern appears in the hash.

Target

Specifies which XML View to load and which App control to render it into.

Pattern

"" = home · about = static · detail/{id} = parameterised · :id: = optional

json — manifest.json routing section
"routing": {
  "config": {
    "routerClass": "sap.m.routing.Router",
    "viewType": "XML",
    "viewPath": "northwind.view",
    "controlId": "app",
    "controlAggregation": "pages",
    "transition": "slide"
  },
  "routes": [
    { "name": "RouteHome",   "pattern": "",                    "target": ["TargetHome"] },
    { "name": "RouteAbout",  "pattern": "about",               "target": ["TargetAbout"] },
    { "name": "RouteDetail", "pattern": "detail/{employeeId}", "target": ["TargetDetail"] }
  ],
  "targets": {
    "TargetHome":   { "viewType": "XML", "viewName": "Home" },
    "TargetAbout":  { "viewType": "XML", "viewName": "About" },
    "TargetDetail": { "viewType": "XML", "viewName": "Detail" }
  }
}

Component.js — Initialise Router

javascript
init: function() {
  // Step 1: call parent — MANDATORY, never skip
  UIComponent.prototype.init.apply(this, arguments);
  // Step 2: start the router — MUST be last
  this.getRouter().initialize();
}
🚫
Calling getRouter().initialize() before UIComponent.prototype.init causes routing to silently fail with no error. Always call parent first.
RoutingSimple Navigation

Navigation Without Parameters

Use navTo(routeName) to navigate to a static view — no data needs to be passed in the URL. The route name must match the "name" field in manifest.json, not the pattern.

javascript
onNavToAbout: function() {
  this.getOwnerComponent().getRouter().navTo("RouteAbout");
}
ℹ️
navTo takes the route name ("RouteAbout"), not the URL pattern ("about"). This is a frequent source of confusion.
RoutingParameterised Navigation

Navigation With Parameters

Pass data in the URL using parameterised route patterns. The parameter key in the navTo call must exactly match the placeholder name in the pattern (e.g. {employeeId}).

Sending — navTo with parameter

javascript — source controller
onSelectEmployee: function(oEvent) {
  var sId = oEvent.getSource()
    .getBindingContext()
    .getProperty("EmployeeID");

  this.getOwnerComponent().getRouter().navTo("RouteDetail", {
    employeeId: sId   // key = placeholder name in manifest pattern
  });
}

Receiving — attachPatternMatched

javascript — destination controller
onInit: function() {
  this.getOwnerComponent().getRouter()
    .getRoute("RouteDetail")
    .attachPatternMatched(this._onMatch, this);
},

_onMatch: function(oEvent) {
  var sId = oEvent.getParameter("arguments").employeeId;
  // sId holds the value from the URL hash
  this._loadEmployee(sId);
},

_loadEmployee: function(sId) {
  this.getOwnerComponent().getModel()
    .read("/Employees(" + sId + ")", {
      success: function(oData) {
        // populate view fields
      }
    });
}

RoutingBack Navigation

Back Navigation

SAPUI5 provides sap.ui.core.routing.History to check whether there is a previous hash to go back to. This enables correct behaviour whether a user navigated into a view normally or arrived via a direct URL/bookmark.

javascript
sap.ui.define([
  "sap/ui/core/mvc/Controller",
  "sap/ui/core/routing/History"
], function(Controller, History) {

  return Controller.extend("northwind.controller.Detail", {

    onNavBack: function() {
      var sPrev = History.getInstance().getPreviousHash();

      if (sPrev !== undefined) {
        // Normal back — use browser history
        window.history.go(-1);
      } else {
        // No history (direct URL) — navigate to home
        this.getOwnerComponent().getRouter().navTo("RouteHome");
      }
    }

  });
});

ODataRead Operations

Read Operations

Data can be read through automatic binding (preferred for lists) or via the explicit model.read() method (used when you need precise control over fetch timing or need to apply filters programmatically).

javascript
var oModel = this.getOwnerComponent().getModel();

// Read a single entity by key
oModel.read("/Employees(1)", {
  success: function(oData) { console.log(oData.FirstName); },
  error:   function(oErr)  { sap.m.MessageToast.show("Error"); }
});

// Read with server-side filter
var oFilter = new sap.ui.model.Filter(
  "City",
  sap.ui.model.FilterOperator.EQ,
  "London"
);
oModel.read("/Employees", {
  filters: [oFilter],
  success: function(oData) { console.log(oData.results); }
});

// Read with $expand — include related Orders
oModel.read("/Employees(1)", {
  urlParameters: { "$expand": "Orders" },
  success: function(oData) { console.log(oData.Orders); }
});

Smart Controlssap.ui.comp

Smart Controls are metadata-driven — they read the OData service's $metadata and automatically generate columns, filter fields, and labels. Zero manual column configuration required.

When to Use Smart Controls

  • In enterprise apps where consistent metadata-driven UI is preferred over custom layouts

Custom Formatters

A formatter is a pure JavaScript function that transforms a raw model value into a display-ready string or type. Formatters are kept in webapp/model/formatter.js and referenced in XML view bindings.

javascript — webapp/model/formatter.js
sap.ui.define([], function() {
  "use strict";
  return {

    statusText: function(sStatus) {
      var map = { "A": "Active", "I": "Inactive", "P": "Pending" };
      return map[sStatus] || "Unknown";
    },

    statusState: function(sStatus) {
      return sStatus === "A" ? "Success" : "Error";
    },

    currency: function(nValue, sCurrency) {
      if (!nValue) return "—";
      return (sCurrency || "$") + " " + parseFloat(nValue).toFixed(2);
    }

  };
});

javascript — controller
sap.ui.define([
  "sap/ui/core/mvc/Controller",
  "northwind/model/formatter"
], function(Controller, formatter) {
  return Controller.extend("northwind.controller.Home", {
    formatter: formatter  // expose to XML View
  });
});

Glossary

Definitions for key terms across HTML, CSS, JavaScript, SAP BTP, Fiori, SAPUI5, OData, and routing.

HTML Web
HyperText Markup Language — defines what exists on a page. The UI5 equivalent is an XML View, which defines what controls exist.
CSS Web
Cascading Style Sheets — defines how things look. In Fiori, prefer the theme and sapUi* helper classes over custom restyling of controls.
JavaScript Web
The language of SAPUI5 controllers. Functions, objects, events, and this are the concepts you must recognise immediately.
DOM Web
The browser’s live HTML tree. Vanilla JS manipulates it directly. UI5 manages it for you via the control tree — avoid document.getElementById in controllers.
Box Model Web
Every element is content + padding + border + margin. Layout bugs in custom CSS are usually a box-model misunderstanding.
Flexbox Web
One-dimensional layout with justify-content and align-items. Mental model behind HBox and VBox.
JSON Web
Text format for objects and arrays. A JSONModel is that shape living in the browser. JSON.stringify / JSON.parse convert between text and objects.
this Web
The object a method was called on. In a controller method written as function, this is the controller — so this.byId() works.
Event Web
A signal that something happened. HTML: addEventListener("click"). UI5: press=".onSave" plus oEvent in the handler.
sap.ui.define Web
UI5’s AMD module loader. Dependency paths in the array become factory-function parameters, in the same order.
BTP BTP
SAP Business Technology Platform — SAP's unified cloud platform. Hosts Cloud Foundry apps, HANA databases, Integration Suite, and all services consumed by Fiori applications.
Cloud Foundry BTP
The PaaS runtime inside BTP. Handles server infrastructure, auto-scaling, and app lifecycle. SAPUI5 apps are deployed here as MTA archives.
BAS BTP
Business Application Studio — browser-based cloud IDE for SAP development. Replaces WebIDE. Accessed from the BTP cockpit; no local install needed.
Dev Space BTP
An isolated containerised environment inside BAS. Each space is pre-loaded with tools for a specific development type (e.g. SAP Fiori).
Destination BTP
A named HTTP connection stored in BTP. Holds base URL, auth type, and proxy settings. Referenced by name in manifest.json so apps never hardcode backend URLs.
MTA BTP
Multi-Target Application — a deployable archive (.mtar) packaging all modules and service bindings. Described by mta.yaml.
mta.yaml BTP
Deployment descriptor defining all modules (app code) and resources (BTP services) for a deployment to Cloud Foundry.
HTML5 Apps Repo BTP
BTP managed service that hosts and serves SAPUI5 static files. All deployed Fiori apps are stored and served from here.
CF CLI BTP
Cloud Foundry Command Line Interface. Used to login (cf login), deploy (cf deploy), and manage apps. Pre-installed in BAS terminals.
Subaccount BTP
An isolated environment within a BTP Global Account. Has its own CF space, service entitlements, and user roles. Trial accounts include one subaccount.
SAP Fiori Fiori
SAP's UX design system and application framework. Defines design guidelines, interaction patterns, and UI standards. SAPUI5 is the technical foundation.
FLP Fiori
Fiori Launchpad — the browser-based home screen showing app tiles. Provides the outer shell, header, notifications, and cross-app navigation.
Shell Fiori
The outer container provided by FLP. Contains header bar, notifications, and user menu. All Fiori apps run inside the shell.
Semantic Object Fiori
A named business entity (e.g. "Employee") used for intent-based navigation in FLP. Combined with an action (e.g. "display") it forms a navigation target.
sap_horizon Fiori
The latest SAP Fiori design theme. Set via data-sap-ui-theme="sap_horizon" in index.html. Provides the modern Fiori 3 visual language.
SAPUI5 SAPUI5
SAP's JavaScript UI framework. Implements MVC, data binding, and a large library of enterprise controls. Powers all Fiori apps.
Component.js SAPUI5
App entry point. Extends UIComponent. Initialises the router and optionally sets up global models. metadata.manifest:"json" is the standard pattern.
manifest.json SAPUI5
App descriptor — defines app ID, data sources, models, routing, and dependencies. The most important file in a SAPUI5 project.
sap.m SAPUI5
The core mobile-optimised control library. Contains Page, Button, Table, List, Input, Dialog, etc. The default library in Fiori apps.
sap.ui.comp SAPUI5
Smart Controls library — SmartTable, SmartFilterBar, SmartForm. Metadata-driven controls that auto-configure from OData annotations.
onInit SAPUI5
Controller lifecycle hook. Fires once when the view is created. The standard place for model setup, router listener registration, and initial data loading.
Fragment SAPUI5
A reusable XML UI snippet without a controller. Typically used for dialogs. Loaded via sap.ui.xmlfragment().
Formatter SAPUI5
A JS function that transforms a model value for display. Defined in formatter.js, referenced in XML as formatter: '.formatter.myFn'.
Expression Binding SAPUI5
Inline logic in XML using {= expression } syntax. Supports ternary, arithmetic, and comparisons without a separate formatter file.
i18n SAPUI5
Internationalisation model. Text stored as key=value in i18n.properties. Referenced in XML as {i18n>keyName}. Mandatory per Fiori guidelines.
MessageToast SAPUI5
Non-blocking brief notification at screen bottom. Use to confirm actions: sap.m.MessageToast.show("Saved!").
MessageBox SAPUI5
Modal confirmation or error dialog. Types: alert, confirm, error, warning. Required before destructive actions per Fiori guidelines.
addDependent() SAPUI5
Attaches a fragment/dialog to the view lifecycle. Ensures proper cleanup when the view is destroyed; prevents memory leaks.
Demo Kit SAPUI5
Official SAPUI5 documentation portal at ui5.sap.com. Contains API reference, live samples, icon explorer, and design guidelines.
growing="true" SAPUI5
Table/List property enabling lazy loading — only a threshold of rows load initially, more appear on scroll. Essential for large datasets.
OData OData
Open Data Protocol — REST standard for exposing data via HTTP. SAP Gateway exposes SAP data as OData. SAPUI5 has a built-in ODataModel.
EntitySet OData
A collection of entities, analogous to a database table. Accessed at e.g. /Employees.
EntityType OData
The type definition (schema) for a single entity — its property names and data types. Smart Controls read EntityType from $metadata.
$metadata OData
Machine-readable schema of the OData service. Access by appending /$metadata to the service URL. Describes all EntityTypes, EntitySets, and relationships.
model.read() OData
Explicit data fetch from an OData path. Returns data in success callback. Used when binding alone is insufficient.
model.create() OData
HTTP POST to create a new entity. Takes entity set path, payload, and callbacks.
model.update() OData
HTTP MERGE/PATCH to update an existing entity. Sends only the fields provided in the payload by default.
model.remove() OData
HTTP DELETE for a specific entity path (with key). Always confirm with the user before calling.
Northwind OData
Public sample OData service at services.odata.org. Contains Employees, Products, Orders, Customers. Read-only. Used as practice backend in development.
$filter OData
URL query parameter for server-side filtering. E.g. ?$filter=City eq 'London'. Passed as filters array in model.read() calls.
$expand OData
URL query parameter to include related entity data in a single request. E.g. ?$expand=Orders includes Order records with each Employee.
Router Routing
SAPUI5 component that watches URL hash changes and activates the matching route. Initialised via this.getRouter().initialize() in Component.js.
Route Routing
A named URL mapping rule in manifest.json routing config. Defines a URL pattern and which target to activate when the pattern matches.
Target Routing
Specifies which XML View to load and which App control to render it into. Activated by a Route match.
navTo() Routing
Programmatic navigation method. Takes route name and optional params: router.navTo("RouteDetail", {id: 1}).
attachPatternMatched Routing
Registers a handler that fires each time a specific route's pattern is matched. Used in the destination controller to extract parameters and load data.
History Routing
sap.ui.core.routing.History — tracks browser navigation history. Used in back navigation: History.getInstance().getPreviousHash().
URL Hash Routing
The fragment after # in the URL (e.g. #/detail/3). SAPUI5 Router reacts to hash changes for SPA navigation — no page reload occurs.
SPA Routing
Single Page Application — the entire app runs in one HTML page. JavaScript swaps view content in response to navigation events, without full page reloads.
